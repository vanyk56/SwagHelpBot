# SwagHelpBot

Discord-бот: автоматически выдаёт роль «игрок» всем новым участникам сервера (бустеры и боты — исключение), а также система тикетов — приватные обращения игроков к администрации.

## Переменные окружения

| Переменная | Обязательно | Описание |
|---|---|---|
| `TOKEN` | да | Токен бота из [Discord Developer Portal](https://discord.com/developers/applications) (вкладка Bot → Reset Token) |
| `ROLE_ID` | да | ID роли, которая выдаётся новичкам |
| `BRAND_COLOR` | нет | Фирменный цвет панелей, hex без решётки (по умолчанию `D99A8C`) |
| `SUPPORT_ROLE_ID` | нет | ID роли администрации — она увидит все тикеты. Если не задать, тикеты видят только участники с правом «Администратор» |
| `TICKET_CATEGORY_ID` | нет | ID категории, в которой создавать тикеты |
| `ENABLE_MESSAGE_CONTENT` | нет | `true` = бот читает текст всех сообщений (нужен включённый Message Content Intent в Developer Portal). **Обязательно для ИИ-триажа** |
| `OPENROUTER_API_KEY` | нет | Ключ с [openrouter.ai/keys](https://openrouter.ai/keys) — включает ИИ-триаж тикетов |
| `OPENROUTER_MODEL` | нет | Модель OpenRouter (по умолчанию `anthropic/claude-haiku-5.5`) |
| `STAFF_ROLE_ID` | нет | ID роли администрации — пингуется при эскалации тикета ИИ |
| `SERVER_NAME` | нет | Название сервера для системного промпта ИИ (по умолчанию `SWAG RUST`) |
| `SERVER_CONNECT` | нет | Адрес connect для промпта ИИ (по умолчанию `157.85.87.131:28061`) |
| `SERVER_SITE` | нет | Сайт сервера для промпта ИИ (по умолчанию `https://swagrust.ru/`) |
| `AI_RULES` | нет | Правила сервера для ИИ одной строкой (`\n` — перенос строки). По умолчанию — встроенный свод правил SWAG RUST |
| `AI_IDLE_CLOSE_MINUTES` | нет | Через сколько минут тишины после ответа ИИ тикет закрывается (по умолчанию `5`) |
| `COMPLAINTS_LOG_CHANNEL_ID` | нет | ID канала, куда ИИ отправляет проверенные жалобы (то же делает команда `/setup-complaints-log`, но переменная переживает редеплои) |
| `GAME_API_SECRET` | нет | Секрет для интеграции с игровым сервером (плагин GlassReportCheck). Одинаковая строка в переменной бота и в конфиге плагина |

## Подготовка бота (один раз)

1. Discord Developer Portal → ваше приложение → вкладка **Bot** → включите **Server Members Intent** (обязательно) и **Message Content Intent** (если используете `ENABLE_MESSAGE_CONTENT=true`).
2. Пригласите бота через OAuth2 → URL Generator (scope `bot`) с правами: **Manage Roles**, **Manage Channels**, **Manage Messages**, View Channels, Send Messages, Read Message History, Attach Files, Embed Links.
3. В настройках сервера перетащите роль бота **выше** роли «игрок».

## Тикеты

Панель в формате Components V2 (фирменная полоса цвета `BRAND_COLOR` слева, выпадающее меню с причинами обращения). Игрок выбирает причину → создаётся приватный канал (видит только он, администрация и бот) → пишет проблему → администрация отвечает прямо в канале → тикет закрывается кнопкой с удалением канала.

Публикация панели: команда `/setup-tickets` в нужном канале (доступна только администрации, панель закрепляется). Один игрок — один открытый тикет.

Бот отвечает на первое сообщение игрока в тикете без тега и упоминаний. Чтобы бот читал текст **всех** сообщений (например, для будущих автоответов), включите Message Content Intent в Developer Portal и поставьте `ENABLE_MESSAGE_CONTENT=true` — иначе бот получает события сообщений, но текст видит только при теге или ответе.

## Жалобы на игроков

Отдельная система от тикетов:

- `/setup-complaints` — опубликовать и закрепить публичную панель жалоб (кнопка «🚨 Подать жалобу»).
- `/setup-complaints-log` — выполнить в закрытом канале администрации: сюда ИИ будет присылать проверенные жалобы.

Флоу: игрок жмёт кнопку → форма (ник, Steam ID по желанию, описание) → приватный канал жалобы → игрок прикрепляет доказательства → **ИИ проверяет полноту** (описание, вложения, Steam ID):

- не хватает данных — ИИ просит доделать; молчание 5 минут — закрытие по неактивности;
- жалоба полная — ИИ формулирует её и отправляет в канал администрации: цель, автор, **число актуальных жалоб на игрока** (включая текущую), резюме и ссылка на канал жалобы; игроку — только подтверждение «передано администрации»;
- мусор/не жалоба/попытка разузнать — вежливый отказ и закрытие.

Счётчик актуальных жалоб считается по открытым каналам жалоб на этого игрока (поиск по Steam ID, при отсутствии — по нику) и **никогда не показывается игрокам** — только в канале администрации. После отправки жалобы в канал администрации ИИ в ней больше не участвует — решение принимают люди.

### Уточнение личности нарушителя по нику

Если игрок указал только ник (без Steam ID), бот использует живую базу игроков игрового сервера (интеграция GlassReportCheck):

- **точное совпадение ника единственное** — бот сам подставляет точный ник и Steam ID (в канал приходит пометка «Личность нарушителя уточнена»);
- **ник примерный или подходит нескольким игрокам** — ИИ перечисляет кандидатов (точный ник + Steam ID) и спрашивает: «этот ли игрок?» После ответа «да» жалоба закрепляется за подтверждённым Steam ID;
- игрок пишет Steam ID прямо в чат — ИИ тоже распознаёт и подставляет его;
- если игрок не может уточнить — жалоба всё равно уходит администрации, личность установят люди.

После уточнения счётчик жалоб, синк в игру и `/game-reports` работают по точному Steam ID. ИИ не может подставить выдуманный ID — принимаются только игроки из базы сервера.

## Интеграция с игровым сервером (GlassReportCheck)

Файл [`plugin/GlassReportCheck.cs`](plugin/GlassReportCheck.cs) (v1.4.0) — та же система репортов и проверок + мост к Discord-боту. Плагин сам опрашивает бота по HTTPS каждые 10 секунд (открывать порты на игровом сервере не нужно) и присылает снимок: все игроки (ники, Steam ID, онлайн), все репорты, проверки, плашки «Проверен».

Настройка:

1. Railway: сервис → **Settings** → **Networking** → **Generate Domain** (получите `https://xxx.up.railway.app`).
2. Railway → Variables: задайте `GAME_API_SECRET` — произвольная длинная строка (секрет).
3. На игровом сервере: замените плагин на новую версию и в конфиге `oxide/config/GlassReportCheck.json` укажите:
   - «Адрес API бота (Railway)» — `https://xxx.up.railway.app`
   - «Секрет API бота» — та же строка, что в `GAME_API_SECRET`
4. `oxide.reload GlassReportCheck`. В консоли сервера появится «Интеграция с Discord-ботом включена», а в логах Railway — `[API:игра] Первый снимок: ...`.

Что появляется в Discord:

- `/game-reports <ник или Steam ID>` — сколько репортов висит на игроке, кто и когда отправил, статус онлайн/проверен/на проверке (только администрация, ответ виден лишь вам).
- `/game-players <поиск>` — база игроков сервера: ник, Steam ID, онлайн, последний вход, число репортов.
- ИИ **видит скриншоты** (PNG/JPG/WebP/GIF до 8 МБ, до 4 последних за запрос) и анализирует их при проверке жалоб и в тикетах. Видео не распознаёт: просит ключевые кадры или передаёт стаффу.
- Новый репорт, отправленный **в игре** через `/report` → бот постит его в канал приёма жалоб с пингом стаффа.
- Жалоба из **Discord** (после ИИ-проверки) автоматически копируется в игровую систему репортов — модераторы увидят её в `/report → МОДЕРАЦИЯ`.
- В посте Discord-жалобы теперь видно и число игровых репортов на игрока.

## ИИ-триаж тикетов

Если задан `OPENROUTER_API_KEY`, каждый тикет обрабатывает ИИ (OpenRouter):

- ИИ видит всю переписку тикета (до 100 последних сообщений) и системный промпт с полным сводом правил SWAG RUST.
- **Первым ответом тикет никогда не закрывается**: ИИ отвечает или уточняет, диалог продолжается с полным контекстом.
- **Игрок подтвердил решение / поблагодарил** → ИИ отвечает и закрывает тикет (канал удалится через 20 секунд; новое сообщение игрока отменяет автозакрытие).
- **Игрок вводит в заблуждение, противоречит себе или манипулирует** → тикет передаётся администрации.
- **Нужно уточнение** → ИИ задаёт вопрос и ждёт ответа; если игрок молчит более `AI_IDLE_CLOSE_MINUTES` минут (по умолчанию 5) — тикет закрывается по неактивности. После эскалации стаффу автозакрытие не действует.
- **Спорно / нет данных в правилах / заявка в Staff / сбой ИИ** → эскалация: английское сообщение с пингом роли `STAFF_ROLE_ID` и кратким резюме, тикет переходит людям.
- **Разбан**: ИИ проверяет, что игрок указал Steam ID, причину и дату бана, затем передаёт тикет администрации — проверять историю банов может только стафф.
- Заявки в Staff всегда уходят администрации сразу, без ИИ.

Правила сервера для ИИ берутся из `AI_RULES` или встроенных в код (файл `index.js`, `DEFAULT_RULES`).

## Деплой на Railway

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → этот репозиторий.
2. Вкладка **Variables** сервиса → добавьте переменные из таблицы выше.
3. **Deploy**. В логах: `Бот запущен как ...`, `Команда /setup-tickets зарегистрирована`.
